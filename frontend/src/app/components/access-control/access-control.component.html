Enable ACL Authorization

Kafka reported that this broker has no ACL authorizer configured. Until one is enabled, brokers reject every ACL request — listing, creating, and deleting are all unavailable, regardless of what this app does. Enabling one is a broker-side change:

1. Add an authorizer to the broker's server.properties

If your cluster runs in KRaft mode (Kafka 3.3+, no ZooKeeper):

authorizer.class.name=org.apache.kafka.metadata.authorizer.StandardAuthorizer
super.users=User:ANONYMOUS

If your cluster still uses ZooKeeper:

authorizer.class.name=kafka.security.authorizer.AclAuthorizer
super.users=User:ANONYMOUS

Adjust super.users to match whichever principal your cluster actually authenticates as — it's shown here as ANONYMOUS because that's Kafka's default when no authentication is configured either.

2. Restart the broker

The authorizer is only read at startup, so the broker needs a restart before this page (or any ACL command) will work.

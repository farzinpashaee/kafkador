How to enable the other metrics topic

Kafkador shows broker and topic metrics by reading the topics that Confluent Server brokers publish their metrics to: {{ telemetryTopic }} and {{ metricsTopic }}. They need Confluent Server (Confluent Platform, the cp-server image); Apache Kafka brokers don't ship these reporters. Enable either one (or both) on every broker:

Option 1 – Confluent Telemetry Reporter → {{ telemetryTopic }}

Add to each broker's server.properties:

metric.reporters=io.confluent.telemetry.reporter.TelemetryReporter
confluent.telemetry.exporter._local.enabled=true
# Only on a cluster with fewer than 3 brokers:
confluent.telemetry.exporter._local.topic.replicas=1
Option 2 – Confluent Metrics Reporter → {{ metricsTopic }}

Add to each broker's server.properties:

metric.reporters=io.confluent.metrics.reporter.ConfluentMetricsReporter
confluent.metrics.reporter.bootstrap.servers=localhost:9092
# Only on a cluster with fewer than 3 brokers:
confluent.metrics.reporter.topic.replicas=1

Or, for the confluentinc/cp-server Docker image, as environment variables:

KAFKA_METRIC_REPORTERS: io.confluent.metrics.reporter.ConfluentMetricsReporter
CONFLUENT_METRICS_ENABLE: 'true'
CONFLUENT_METRICS_REPORTER_BOOTSTRAP_SERVERS: broker:29092
CONFLUENT_METRICS_REPORTER_TOPIC_REPLICAS: 1
Then
  • To enable both, list the reporters comma-separated in a single metric.reporters line.
  • Restart the brokers one at a time. Each reporter creates its topic the first time it publishes, usually within a minute.
  • If the cluster uses ACLs, allow Kafkador's principal READ and DESCRIBE on both topics.
  • Refresh this tab. Property names can differ between Confluent Platform releases; if a topic still doesn't appear, check the reporter's documentation for your version.
